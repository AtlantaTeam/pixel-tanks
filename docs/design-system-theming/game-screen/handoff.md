# Handoff: Боевой экран `/game` (issue #280)

## Обзор (ревизия 2 — после ревью по issue #280)

Финализированный игровой экран Pixel Tanks: Canvas-арена + оверлейный HUD + тач-рогатка.
Заменяет легаси-макет `views/game-page` + `widgets/game-controls` (очковая модель, счётчики
«− 10 +», нативный дропдаун снаряда, клавиатурная подсказка на мобилке).
Модель боя — **два HP-бара** (GDD §2.5), очки уходят.

## О файлах в пакете

Файлы этого бандла — **дизайн-референсы, написанные на HTML**. Это прототипы, показывающие
итоговый вид и поведение, а **не production-код для копирования**. Задача — пересобрать
эти экраны в существующей среде кодовой базы (Next.js + React + Tailwind 4 + FSD,
компоненты `shared/ui`), по её паттернам, а не переносить HTML как есть.

Файлы:

- `game-screen-final.dc.html` — экспорт-секция: решения A–G, кадры 390/768/1280/1920,
  кадры состояний, кадры контраста над скинами, таблица размеров. Открывается в браузере.
- `pt-game.dc.html` — сам экран, параметризованный: `variant` (m/t/d/w), `state`
  (turn/aim/bot/flight/bubble/empty/over), `outcome` (victory/defeat), `skin` (dark/sand),
  `intensity` (neon/calm). Все кадры — это он с разными пропами.
- `support.js` — рантайм Claude Design для локального открытия `.dc.html`; в репозиторий
  намеренно не коммитится (см. `README.md` рядом).
- `../token-spec.md` — исходная спека токенов, тем и компонентов.

## Фидельность

**High-fidelity.** Цвета, типографика, размеры и состояния финальные — воспроизводить 1:1
на существующих компонентах `shared/ui` (`HPBar`, `PipRow`, `WeaponSelector`, `ChatBubble`,
`FactionBadge`, `Panel`, `Button`, `Dialog`, `Toggle`, `Icon`). Новых атомов не требуется;
новое здесь — только композиция экрана и состояния.

## Экраны / кадры

### Боевой экран, мобильная вертикаль (390×844) — эталон

**Назначение:** ход игрока: прицелиться рогаткой по Canvas и выстрелить.

**Layout:** `h-dvh`, `safe-area-inset`, без горизонтального скролла.
Арена — `position:absolute; inset:0` (весь экран). HUD лежит **оверлеем** поверх арены:

| Слой                                 | Позиция                                                                                                                                                                                                         | Содержимое                                                                                                                                                |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Верхний HUD                          | `absolute; top:0; left:0; right:0; z-index:6`; padding `calc(10px + env(safe-area-inset-top)) 10px 0`; `flex-column; gap:8px`                                                                                   | ряд из двух HP-карточек (`flex:1` каждая, `gap:8px`); ниже ряд: пилюля хода + spacer + mute 44×44 + пауза 44×44                                           |
| Телеметрия (внутри верхнего оверлея) | последний блок того же `flex-column`; ряд 1: УГОЛ и СИЛА с кнопками ± 44×44; ряд 2: ВЕТЕР + ячейка пипов (СНАРЯДЫ 5, ХОДЫ 4)                                                                                    | НЕ позиционируется от низа: телеметрия обязана лежать в верхнем оверлее, иначе она садится на танки при любом процедурном рельефе                         |
| Палуба                               | `absolute; left:0; right:0; bottom:0; z-index:6`; фон `linear-gradient(180deg, rgba(8,12,8,0), rgba(8,12,8,.92) 26%)`; padding `26px 10px calc(12px + env(safe-area-inset-bottom,8px))`; `flex-column; gap:8px` | селектор оружия (‹ 48×48, панель `flex:1`, › 48×48); ряд манёвра ‹ › (56×64 каждая) + кнопка ОГОНЬ (`flex:1; min-height:64px`); строка-подсказка про жест |

**Безопасные зоны (жёсткое правило):** верхний оверлей занимает 242px, палуба 196px.
Между ними — **зона жеста**: `left/right:10px`, `top:242px`, `bottom:196px`, показана
пунктиром 2px `var(--accent)` `opacity:.3` с меткой «ЗОНА ЖЕСТА» в правом верхнем углу.
**Пунктир и метка — аннотация макета, а не элемент прода** (проп `showGestureZone`, по
умолчанию выключен): постоянная рамка поверх арены мешала бы. Игрок узнаёт про жест из
подсказки в палубе и из онбординга. Внутри зоны не должно
быть ни одного HUD-элемента и ни одной тач-цели. Оттяжку можно начинать только внутри
зоны; при выходе пальца за её границы во время оттяжки жест продолжается (pointer capture),
луч и кольцо продолжают рисоваться, чип прижимается к верхней границе зоны и никогда не
уходит под палубу. Танки и траектория живут в этой же зоне — поэтому правило не зависит
от высоты рельефа.

### Планшет (768×1024)

Собственная раскладка, а не растянутая мобилка. Верхняя полоса-панель (`bg --color-panel`,
`border-bottom:2px`, padding `12px 16px`) — **два ряда** через `flex-wrap`: ряд 1 — HP-бары
(`flex:1; min-width:420px`) + пилюля хода + mute/пауза; ряд 2 (`width:100%`) — телеметрия.
В один ряд всё это не влезает в 768: телеметрия уезжала за правый край, а HP-бары
схлопывались первыми. Кнопки ± на планшете не показываются (доводка — только тач-мобилка).
Высоту полосы НЕ хардкодить в отступе арены: арена — `inset:0` во весь экран, полоса
просто рисуется поверх неё (`z-index:6`, непрозрачный `--color-panel`). Хардкод `top:202px`
давал 14px шва бэкграундом, когда реальная высота ряда изменилась. То же правило
на мобилке: арена всегда `top:0; bottom:0`, HUD — оверлей; тач-контролы разведены по нижним
углам как угловые кластеры (`align-items:flex-end; justify-content:space-between`,
padding `0 16px calc(18px + safe-area)`): слева селектор оружия (280px), справа манёвр +
ОГОНЬ (340px). Зона жеста здесь — `top:96px; bottom:132px`.

### Десктоп (1280×760) и широкий (1920×960)

HUD распрямляется в полосы:

- верхняя полоса `height:78px`, `bg var(--color-panel)`, `border-bottom:2px var(--color-border)`,
  `padding:0 18px`, `display:flex; align-items:center; gap:20px` — HP-бары (`flex:1`),
  пилюля хода, mute, пауза;
- арена `absolute; top:78px; bottom:124px; left:0; right:0`;
- нижняя полоса `height:124px`, `bg var(--color-panel)`, `border-top:2px var(--color-border)`,
  `padding:14px 18px`, содержимое по центру, `gap:18px`: селектор оружия (`width:300px`),
  манёвр, ОГОНЬ (`min-width:200px`), под ними строка клавиатурной подсказки;
- телеметрия — в той же верхней полосе, в один ряд с HP-барами, цифры 22px, без кнопок ±
  (доводка с клавиатуры);
- на 1920 обе полосы центрируются `max-width:1280px; margin:0 auto`, нижняя
  распределяется `space-between`: оружие — ОГОНЬ с манёвром (`flex:1; max-width:420px`) —
  клавиатурная подсказка.

## Взаимодействия и состояния

**Прицеливание (`aim`)** — жест «оттяни-отпусти» уже в движке (`game-canvas.tsx`,
pointer-события, `setPointerCapture`, `touch-none`). Визуал:

- **короткий сегмент** от ствола: ~12% пути, `stroke var(--accent)`, `stroke-width:2`,
  `stroke-dasharray:6 8`, `opacity:.85`. Точка падения НЕ показывается (вердикт по п.3):
  полная дуга отменяет пристрелку и «читаемый провал по своей вине» из GDD. Полная дуга
  допустима только как assist онбординга / первого боя с явным выключателем в настройках;
- луч оттяжки от точки касания: 2px `var(--accent)` + `var(--glow)`, точка старта 8×8;
- кольцо пальца: 56×56, `border:2px dashed var(--accent)`, `border-radius:50%`, `opacity:.7`;
- чип предпросмотра — **выше пальца, внутри зоны жеста** (палец закрывает низ-право),
  с подписью-напоминанием «только направление · падение не показываем»: угол 22px
  `var(--accent)`, сила 22px `--color-warning`, оба `tabular-nums` + `--glow-text`,
  подпись «ОТПУСТИ — ВЫСТРЕЛ» 9px;
- HUD-числа в этот момент ведомые (значения те же, чип — главный);
- **превышение максимума**: луч и чип перекрашиваются в `--color-danger`, сила фиксируется
  на 100, чип показывает «МАКС».

**Ход бота (`bot`)** — корень получает `data-faction="enemy"` (весь `--accent` → маджента),
арена в рамке `inset 0 0 0 3px var(--color-enemy)` + `inset 0 0 40px rgba(201,0,255,.28)`,
короткий сегмент направления ствола бота (~12%, `dasharray:6 8`) и вспышка выстрела 14×14 —
**без предсказания траектории**: игрок не должен знать заранее, попадёт ли соперник, иначе
ход бота теряет напряжение. Палуба закрыта локом.

**Полёт снаряда (`flight`)** — снаряд 10×10 `--color-warning` + `0 0 12px`, след —
градиентная линия 2px. Палуба закрыта локом.

**Лок ввода (общий для bot и flight)** — оверлей на ВСЮ палубу `rgba(8,12,8,.88)`
(`.92` на светлом скине) + `blur(3px)` + `inset 0 0 0 1px rgba(0,0,0,.9)`; контролы под ним
не просвечивают как грязь. По центру мигающий квадрат 10×10 `var(--accent)`
(`blink 1s infinite`) и подпись
DotGothic16 15px uppercase: «ХОД СОПЕРНИКА» / «СНАРЯД В ПОЛЁТЕ».
Смысл: игрок читает «сейчас нельзя», а не «залипло».

**Патроны кончились (`empty`)** — `×0`, disabled только ОГОНЬ и селектор оружия;
**манёвр активен, пипы ХОДЫ показывают 2 из 4** — тост обещает манёвр, значит манёвр
должен быть возможен. Тост `role="status"` над палубой (`bottom:196px`, ничего не перекрывает, рамка 2px + левая 4px `--color-warning`,
иконка `warning` 16px): «Патроны кончились — остался только манёвр. Ход перейдёт сопернику.»

**Game over (`over`)** — оверлей `rgba(4,8,4,.78)`; диалог `max-width:340px`, padding 24px,
`bg --color-panel`, `border:4px var(--color-border-strong)`, `box-shadow:0 6px 0 rgba(0,0,0,.55)`,
`gap:18px`. Заголовок DotGothic16 34px uppercase `var(--accent)` + `var(--glow)`:
«ПОБЕДА» / «ПОРАЖЕНИЕ». Корень несёт `data-outcome="victory|defeat"` (defeat → `--accent` = danger).
Пилюля хода на финале СКРЫТА (бой окончен — индикатора хода быть не может).
Статистика — четыре строки `space-between`, значения `tabular-nums`: Урон 128, Точность 62 %,
**Выстрелов 6**, **Манёвров 3 / 4** («Ходов 14» было неверно: бюджет манёвра — 4 на матч, GDD §2.3).
Кнопки (все `min-height:48px`, 14px `letter-spacing:.1em` uppercase, стопкой):
`Реванш` — единственная залитая (primary) → `Поделиться реплеем` контурный accent
(рамка 2px + текст `var(--accent)`, без заливки) → `В меню` ghost `--color-border-strong`.
Главное действие обязано доминировать: две залитые кнопки соревновались за внимание.

**Клавиатурная подсказка** — только в нижней полосе на 1280+; строки
`← → угол`, `↑ ↓ сила`, `Ctrl + ← → манёвр`, `Space выстрел`, 10px `--color-text-dim`,
`gap:14px`. Показывать по `@media (hover:hover) and (pointer:fine)` — на тач-устройствах
её не должно быть в DOM-выдаче/в видимости. Вместо неё на моб./планшете одна строка внутри палубы
10px uppercase `--color-text-muted` **с подложкой, blur и рамкой 2px по правилу E**
(без подложки она пропадала на светлом скине): «Тяни по арене — отпусти, чтобы выстрелить».

**Кнопка ОГОНЬ против рогатки (решение B)** — жест целится и стреляет; ± на ячейках УГОЛ
и СИЛА правят числа на градус, кнопка выстреливает именно ими (подпись называет числа).
Без доводки на тач-брейкпоинтах кнопка была необъяснима — поэтому ± вернулись на мобилку.
Кнопка не крупнее 64px и не занимает центр thumb-зоны. Если плейтест покажет, что игроки
целятся кнопками вместо рогатки — убирать надо кнопку, а не жест.

**Ветер (вердикт по п.18)** — до первого выстрела: стрелка направления + 3 пипа грубой силы
(2 из 3). После первого выстрела ячейка раскрывается в точное `→3` до конца боя.
Точное число с первого кадра убивает пристрелку из GDD; скрывать его весь бой — штраф за
память, а не интрига. Флаг состояния — `windRevealed`.

**Контраст над любым скином (решение E)** — единое правило для КАЖДОГО HUD-элемента:
подложка `rgba(8,12,8,.80–.86)` + `backdrop-filter: blur(4px)` + рамка 2px токеном роли +
внешний контур `0 0 0 1px rgba(0,0,0,.9)`. Контур держит границу над светлым песком,
blur — над шумным рельефом. Цвета арта (небо, рельеф, спрайты) в контракт HUD не входят:
арена, фон и танки — сменяемый арт (биомы, скины).

**Спокойный HUD (решение G)** — `[data-intensity="calm"]` на корне обнуляет `--glow-*`
и `--glow-text`; цвета, рамки и иерархия сохраняются.

**prefers-reduced-motion** — гасить `blink`, пульсацию лока и анимацию печати бабла
(текст показывать сразу).

## Состояние

- `hp.player`, `hp.enemy` (0..100) — **заменяют** `playerPoints` / `enemyPoints` в `game.store`
  (отдельная агентская issue, блокер интеграции).
- `turn: 'player' | 'enemy'` → `data-faction` на корне.
- `phase: 'idle' | 'aiming' | 'flight' | 'resolving' | 'over'` → лок ввода и подписи.
- `angle`, `power` (в оттяжке приходят из `calculateDragAim`), `wind`, `windRevealed`.
- `weapons[]`, `selectedWeapon`, `moves` (бюджет 4), `shotsFired`, `ammoPips`, `movePips`.
- `botReply` (текст + таймер жизни ~3 с), `outcome: 'victory' | 'defeat'`.
- `intensity: 'neon' | 'calm'` — пользовательская настройка, персистится.

Эффекты: `--glow-accent`, `--glow-primary`, `--glow-enemy`, `--glow-danger`,
`--glow-text: 0 0 8px currentColor`, `--edge-pixel: 0 3px 0 #05140a`.
Темы: `[data-faction=player|enemy]`, `[data-outcome=victory|defeat]`, `[data-intensity=calm]`.
Эффекты-канон из кода: `--glow-enemy: 0 0 6px rgba(201,0,255,.55), 0 0 18px rgba(201,0,255,.35)`;
`calm` гасит все `--glow-*` и `--glow-text` в `0 0 0 transparent` (не `none`) — канон кода,
стили макета приведены в соответствие.
Шрифты: дисплейный — `DotGothic16` (кириллица), UI и все числа — `JetBrains Mono` 400/500/700,
`tabular-nums` везде, где есть цифры. Handjet и Pixelify Sans убраны полностью (решение D7).
В проде шрифты self-hosted из `public/fonts`; Google CDN в макете — только чтобы прототип
открывался в браузере, в код не переносить.
Радиусы: 0 (пиксельная эстетика). Рамки: 2px контролы, 3–4px панели и диалоги.
