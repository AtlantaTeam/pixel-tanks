# PRD: Дизайн-система и темизация из hero-визуала (design-system-theming)

**Дата**: 2026-07-24
**Статус**: ✅ реализовано — PR #296, milestone закрыт: токены `@theme`, темы `[data-faction]`, витрина `/design-system`. Статус — [доска](https://github.com/orgs/AtlantaTeam/projects/1) + milestones. Ниже — исходный PRD как исторический документ.

## Цель

Вывести цельную дизайн-систему pixel-tanks **из существующего основного визуала** (hero-арт `docs/images/pixel-tanks-hero.png` + `public/videos/main-hero.mp4`) — палитра, типографика, эффекты, темы — и кодифицировать её в семантические `@theme`-токены как единый источник правды. Это **определяющая, человеко-вкусовая** сторона (дизайнер работает через **Claude Design**), которую затем энфорсит машинный барьер (`design-consistency-gate`). Сейчас тема — приглушённый Pico-8 сабсет (`docs/game-ui/prd.md`), а hero-арт заметно сатурированнее и неоновее — этот зазор надо осознанно закрыть.

## Пользовательские сценарии

- Дизайнер (человек) выводит палитру и темы из hero-арта в **Claude Design** → переносит результат в `@theme`-токены репо (единый источник правды).
- Разработчик/агент строит UI из **семантических токенов** (`bg-surface`, `text-primary`), а не хардкод-хексов → экраны консистентны с айдентикой игры.
- Пользователь видит единый визуальный язык на всех экранах (меню, HUD, лидерборд, game-over), согласованный с hero-видом.
- Акценты переключаются между **темами** (напр. `player`/`enemy` — зелёная/фиолетовая фракции) сменой набора токенов, без правки компонентов.

**Принцип**: PRD задаёт цель, структуру и ограничения, но **НЕ фиксирует конкретные визуальные решения**. Шрифт(ы), точную палитру, сатурацию, набор эффектов, число и вид тем — выбирает **Claude Design** (человек). Ниже — рамки, не предписания; существующие значения (Pico-8, Press Start 2P) — стартовая точка, которую можно пересмотреть.

- **Аудит палитры**: текущий Pico-8 сабсет vs hero-арт как вход; целевую палитру/сатурацию определяет Claude Design.
- **Семантические токены** в `globals.css` `@theme` (набор — на усмотрение Claude Design, ориентир: `surface/panel/primary/accent/danger/muted/ink` + эффекты при необходимости), покрывающие текущие экраны.
- **Типографика**: выбор шрифта(ов), ролей и scale — **свобода Claude Design**; единственное жёсткое требование — поддержка кириллицы.
- **Темизация** (≥1 тема) через `@theme` + CSS-переменные Tailwind 4; конкретные темы (напр. `player`/`enemy`) — на выбор Claude Design; в скоупе — механизм переключения.
- **Кодификация** результата Claude Design в `@theme` (один источник правды, без параллельного).
- **Токен-справочник** (`docs/design-system-theming/`): значение и применение каждого токена + как выведен из арта.

## Не в скоупе

- Машинный энфорсмент (линт токенов, визрегрессия) — это отдельный PRD `design-consistency-gate`; **этот PRD его питает** (определяет токены, которые тот энфорсит).
- Миграция токенов на DTCG / Style Dictionary — пока `@theme` достаточно.
- Ремейк спрайтов/арта — используем существующий hero-визуал как есть.
- Глобальные light/dark темы всего сайта — держим игровую тему (если не решим иначе).
- Переносимый дизайн-адаптер ralph (#262).

## Технические ограничения

- Механизм тем — **Tailwind 4 `@theme` + CSS-переменные** (токены = CSS vars); не изобретать параллельный.
- **Кириллица**: любой выбранный Claude Design шрифт обязан её поддерживать (игра русскоязычная).
- **Контраст WCAG**: неоновые цвета на тёмном фоне — проверять читаемость HUD/текста.
- **Claude Design** на `api.anthropic.com`/`claude.ai` → из РФ работает через Shadowsocks-туннель (дизайнер учитывает доступ со своей машины).
- Переименование/добавление токенов не должно ломать существующие `shared/ui`-компоненты и экраны — миграция входит в работу.
- Источник правды один — `@theme` в `globals.css`; Claude Design не создаёт второй источник (его вывод переносится в токены).

## Критерии готовности

- [ ] Палитра выведена из hero-арта и зафиксирована; решение по сатурации/неону принято и задокументировано.
- [ ] Полный набор семантических токенов в `globals.css` `@theme` (набор — как решил Claude Design), покрывающий текущие экраны.
- [ ] Реализована ≥1 темизация через `@theme`/CSS-переменные, переключаемая без правки компонентов.
- [ ] Типографика выбрана и формализована (шрифт(ы) — на усмотрение Claude Design, с поддержкой кириллицы; роли + scale).
- [ ] Токен-справочник задокументирован в `docs/design-system-theming/` (значение и применение каждого токена, связь с hero-артом).
- [ ] Существующие `shared/ui`-компоненты и экраны переведены на новые семантические токены (нет хардкод-цветов вне `@theme`); `lint`, `lint:fsd`, `typecheck`, `test` зелёные.
- [ ] Контраст ключевого текста/HUD проверен на читаемость на тёмном фоне (Playwright-скриншот или ручная проверка).

## Связь с другими фичами

- **→ `design-consistency-gate`** (барьер): энфорсит токены/консистентность, определённые здесь. **Порядок: сначала эта фича, потом барьер** (нельзя энфорсить несформированную систему).
- **→ #262** (переносимый дизайн-адаптер ralph): токены и темы, выведенные здесь, — прообраз «конфиг-части» адаптера.
