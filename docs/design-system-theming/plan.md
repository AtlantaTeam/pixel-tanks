# Plan: design-system-theming

**PRD:** [docs/design-system-theming/prd.md](./prd.md)
**Дата:** 2026-07-24

Дизайн-система и темизация выводятся из hero-визуала. **Фаза 1 — человеческая** (дизайн в Claude Design, НЕ для автономного ralph): она производит token-spec, который потребляют агентские фазы 2–5. Ралф-очередь для фаз 2–5 поднимаем только ПОСЛЕ завершения фазы 1.

> ✅ **Реализовано, milestone закрыт (PR #296).** Помимо фаз 1–5 ниже в ходе работы добавлена и сделана **Фаза 6 — витрина дизайн-системы** (in-app роут `/design-system` как мишень визрегрессии; issue #290, `src/views/design-system/`). Статус — [доска](https://github.com/orgs/AtlantaTeam/projects/1) + milestones, не чекбоксы плана.

## Фазы реализации

### Фаза 1 [ЧЕЛОВЕК]: Определение дизайн-системы из арта (Claude Design)

**Цель:** конкретная, кодифицируемая спецификация системы, выведенная из hero-арта и видео.
**Затрагивает:** design (человек, Claude Design) — не для ralph.
**Задачи:**

- [ ] Аудит: текущий Pico-8 сабсет (`docs/game-ui/prd.md`) vs hero-арт как вход.
- [ ] Вывести палитру и решить целевую сатурацию/неон.
- [ ] Выбрать шрифт(ы) (обязательна кириллица), эффекты (glow/outline/…) и ≥1 тему.
- [ ] Зафиксировать `docs/design-system-theming/token-spec.md`: имена + значения токенов, шрифты, темы.

**Когда готова:** `token-spec.md` одобрен человеком — конкретные значения/шрифты/темы, готовые к кодификации.

### Фаза 2 [АГЕНТ, tracer bullet]: Сквозной срез — ядро токенов + одна тема + один компонент

**Цель:** доказать пайплайн token-spec → `@theme` → компонент → переключение темы → рендер.
**Затрагивает:** frontend.
**Задачи:**

- [ ] Ядро семантических токенов + одна тема (CSS-переменные) в `globals.css` `@theme` по token-spec.
- [ ] Подключить один компонент (`Button`) к семантическим токенам.
- [ ] Включить переключение темы для этого среза.
- [ ] Unit-тест токенов/темы + Playwright-скриншот в `screenshots/`.

**Когда готова:** `Button` рендерится из семантических токенов, тема переключается, скриншот подтверждает; `lint`/`typecheck` зелёные.

### Фаза 3 [АГЕНТ]: Полная кодификация токенов + типографика + справочник

**Цель:** вся система из спеки — в коде.
**Затрагивает:** frontend.
**Задачи:**

- [ ] Все семантические токены из `token-spec.md` в `@theme`.
- [ ] Подключить выбранную типографику (шрифты/scale) через `next/font` (self-host).
- [ ] Токен-справочник `docs/design-system-theming/tokens.md` (значение + применение каждого токена).
- [ ] Тесты на присутствие/корректность токенов.

**Когда готова:** все токены и типографика из спеки в `@theme`; справочник задокументирован; тесты зелёные.

### Фаза 4 [АГЕНТ]: Миграция shared/ui и экранов на семантику

**Цель:** весь UI на семантических токенах, нет хардкод-цветов.
**Затрагивает:** frontend.
**Задачи:**

- [ ] Перевести `Button/Panel/Select/Dialog` на семантические токены.
- [ ] Перевести экраны (`main-page`, `game-controls`, `game-over`).
- [ ] Убрать хардкод-цвета вне `@theme`.
- [ ] Обновить/добавить тесты компонентов.

**Когда готова:** нет цветовых хардкодов вне `@theme`; `lint`, `lint:fsd`, `typecheck`, `test` зелёные; Playwright — экраны в новой теме, консоль чистая.

### Фаза 5 [АГЕНТ]: Темизация (переключаемые темы) + контраст

**Цель:** рабочая темизация + проверенная читаемость.
**Затрагивает:** frontend.
**Задачи:**

- [ ] Механизм переключения тем (≥1 тема из спеки) через `@theme`/CSS-переменные без правки компонентов.
- [ ] Проверка WCAG-контраста HUD/текста (Playwright-скриншоты по вьюпортам 390px/десктоп).
- [ ] Тест переключения темы.

**Когда готова:** тема(ы) переключаются без правки компонентов; контраст ключевого текста/HUD подтверждён; тесты зелёные.

## Порядок и связи

- **Фаза 1 (человек) → блокирует фазы 2–5** (агент): без token-spec кодифицировать нечего.
- После этой фичи — **`design-consistency-gate`** (барьер: линт токенов + визрегрессия) энфорсит созданное.
- Токены/темы — прообраз «конфиг-части» переносимого дизайн-адаптера **#262**.
