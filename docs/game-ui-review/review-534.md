# UI/UX-разбор боевого экрана (issue #534)

Разбор по кадрам `docs/game-ui-review/shots/` и по коду `top-hud`, `game-controls`,
`hp-bar`, `pip-row`, `game-canvas`, `docs/design-system-theming/token-spec.md`.
Ни одно предложение по HUD не требует увеличения бюджета 174 / 78 px.

## Приоритеты (эффект на правку)

| Ранг | Что делаем                                                                                                                                                    | Объём                |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------- |
| P0   | Три подтверждённых кадрами дефекта: клип HUD на 320; высота HUD на 768 (~245) против объявленного в коде инсета зоны жеста 128; два бейджа об одном состоянии | часы, без нового UI  |
| P1   | Квантование взрыва в пиксельную сетку + кратер по типу оружия (§5)                                                                                            | одна функция рендера |
| P2   | Сетка: шаг 4, три легальные высоты ячейки, `stretch` вместо `items-center` (§1)                                                                               | разметка HUD         |
| P3   | Иерархия: убрать ячейку «Снаряды» с десктопа, ветер поднять в класс угла/силы (§2, §3)                                                                        | разметка HUD         |
| P4   | Небо: тонировка земли от времени суток, светило, тень, три класса облаков (§6)                                                                                | рендер сцены         |

## 1. Сетка и ритм

**Решение.** Шаг 4 px, все отступы и высоты кратны 4. Легальны три зазора: **4** — внутри
ячейки, **8** — между ячейками группы, **16** — между группами. Высота ячейки — из набора
**{32, 44, 56}** (32 — служебная строка без тач-цели, 44 — минимальная тач-цель, 56 — ячейка
с числом HUD-кегля). Значений 28, 34, 40, 50, 52, 55, 72 в наборе нет.
Выравнивание — **`stretch`, не `items-center`**: ячейки получают высоту ряда, число садится
на общую линию за счёт одинаковой внутренней сетки (метка 12 → зазор 4 → значение 36).

Бюджеты сходятся: мобилка 8 + 32 + 8 + 48 + 8 + 56 + 8 = **168** из 174 (6 px в запас);
десктоп 1 + 10 + 56 + 10 + 1 = **78** (единственное задокументированное исключение из
кратности 4 — паддинг полосы 10 px, потому что 78 задано снаружи).

**Обоснование.** На кадре 1280 правая группа даёт пять верхних кромок в одном ряду
(72/72/50/28/28) — глаз читает лестницу, а не полосу приборов. Разнобой не несёт информации:
ни один размер не означает «важнее».

**Проверка.** Тест `hud-grid-rhythm`: в каждом ряду все дети имеют равный `offsetHeight` ∈
{32,44,56}; все `gap`/`padding` ∈ {4,8,16} + белый список (10); `hud-geometry-stable` и
`overlay-budget` не краснеют; глазами — по верхней кромке ячеек ряда проводится одна линия.

## 2. Иерархия

**Решение.** Ранжируем по частоте изменения, не «по важности вообще»:

| Класс          | Что входит                | Подача                                          |
| -------------- | ------------------------- | ----------------------------------------------- |
| 1 · непрерывно | угол, сила                | кегль 40, tabular-nums, glow, карточка          |
| 2 · раз в ход  | HP обоих, ветер, ходы     | кегль 20 / полоса / пипы, карточка без glow     |
| 3 · состояние  | чей ход, лок, звук, пауза | цвет и рамка арены; текст — одна плашка, не две |

Следствия: (а) ветер поднимается из класса 3 в класс 2 — единственный внешний фактор,
который игрок не контролирует; (б) ячейка «Снаряды» на десктопе удаляется — дубль селектора
палубы («Фугас ×2»), стоит ~90 px в самом тесном месте полосы; (в) glow остаётся у двух
сущностей: активная сторона и класс 1. Сейчас светится почти всё, поэтому не светится ничто.

**Обоснование.** На кадрах прицеливания на первое место претендуют одновременно glow-карточка
HP игрока, glow-плашка «ТВОЙ ХОД», зелёное «360°» и золотое «10».

**Проверка.** Скриншот HUD с `blur(8px)` → должно остаться три светлых очага (сейчас шесть);
число элементов с непустым `--glow*` ≤ 2; ширина правой группы на 1280 ≤ 420 px и её `right`
внутри полосы (числовой чек регресса #489).

## 3. Поведение по брейкпоинтам

| Блок         | 320–767                                | 768–1279                                 | ≥1280                             |
| ------------ | -------------------------------------- | ---------------------------------------- | --------------------------------- |
| HP обоих     | inline, ник 6ch, число HP скрыто < 360 | inline, ник 16ch, карточки равной ширины | inline, ник 16ch (не 10ch)        |
| Статус хода  | плашка на всю ширину ряда              | плашка по контенту                       | плашка ≤ 180 px, лок — в ней же   |
| Угол · Сила  | карточка с ±, не сжимается             | карточка с ±                             | карточка без ±, клавиатура        |
| Ветер        | стрелка + 3 пипа 10×10, потом число    | то же, высота 56                         | число + стрелка, кегль как у силы |
| Снаряды      | в карточке «Ресурс» с ходами           | то же                                    | **убрать** — дубль палубы         |
| Ходы         | вторая строка «Ресурса»                | то же                                    | своя карточка 56                  |
| Звук · Пауза | 44×44 у правого края ряда 2            | 44×44 в правом углу строки 1             | 44×44 на стыке групп              |

**Порядок сброса при нехватке ширины:** 1 — текстовые метки ячеек (в `aria-label`);
2 — «Снаряды»; 3 — число HP; 4 — ник (6ch → иконка стороны); 5 — пипы ветра → стрелка.
Никогда не уходят: полоса HP, статус, угол, сила, ходы, звук, пауза.

**Особая точка 768 — дефект, а не вкусовщина.** На кадре панель занимает ~245 px, а не
заявленные 128: планшет получил мобильную структуру из трёх рядов с пустой правой половиной
и кнопками звук/пауза в середине пустого ряда. В коде зона жеста на ≥768 объявлена как
`md:top-[128px]` (`GESTURE_ZONE_INSET`, `game-canvas.tsx`) — верхние ~117 px зоны
прицеливания лежат под панелью. Комментарий там прямо предупреждает, что e2e ловит только
горизонтальный overflow, но не вертикальное выравнивание зоны, — этот случай он не поймал.
Решение: 768–1279 — две строки на всю ширину, `justify-between`: строка 1 — HP + HP слева,
статус и звук/пауза справа; строка 2 — телеметрия слева, «Ресурс» справа. Бюджет 44 + 56 +
зазоры = **124**, укладывается в объявленные 128.

**Проверка.** На всех 11 ширинах `scrollWidth === clientWidth` для каждого ряда и `right`
каждой ячейки внутри полосы (на 320 сейчас падает); высота HUD на 768 ≤ 128 и сравнивается
тестом с константой инсета зоны жеста; набор присутствующих `data-testid` ячеек на каждой
ширине зафиксирован как ожидаемый.

## 4. Известные места — вердикты

1. **Разные высоты в ряду — подтверждаю**, это главный источник «неаккуратности». Лечится §1
   без затрат по высоте.
2. **Снаряды и ходы без подложки — подтверждаю, но лечить не подложкой.** Добавить две
   карточки в самое тесное место полосы (там жил #489) — плохой обмен. На десктопе «Снаряды»
   удалить как дубль, «Ходы» получают карточку 56; на мобиле оба живут в одной карточке
   «Ресурс» двумя строками пипов. Подложка есть у всего, а ячеек стало меньше.
3. **Зазор 14 против 6 — обоснование принимаю, выражение меняю.** Правило: _ритм считается
   по хит-зонам, а не по визуальным боксам_. Зазор между хит-зонами ≥ 8; если тач-цель шире
   бокса, разница добирается зазором из легального набора — **16, а не 14** — и трактуется
   как «зазор между группами» («Угол + Сила» / «Ветер + Ресурс»). Ширина сходится:
   16/4/4 = 24 против нынешних 14/6/6 = 26, то есть на 390 освобождается 2 px.
4. **Новое: 320 клипается.** Кнопка паузы срезана правым краем, ячейка «Снаряды/Ходы»
   отсутствует — ряд 3 переполнился и вытолкнул её. Тот же класс, что #489, на нижней границе
   поддержки.
5. **Новое: два бейджа об одном состоянии.** На explosion-1280 одновременно «ВЫСТРЕЛ» и
   «ЗАМОРОЖЕНО», плюс «СНАРЯД В ПОЛЁТЕ» внизу и маджента-рамка арены — четыре сообщения об
   одном. Оставить два: рамку и плашку статуса. Освободится ~120 px там, где ник обрезается
   до «Rex Comman…».
6. **Новое: ник длиннее на планшете, чем на десктопе.** На 768 «Rex Commander» целиком, на
   1280/1920 — усечён. Обратная зависимость от ширины читается как баг; причина —
   фиксированная ширина HP-карточки на десктопе.
7. **Новое, требует проверки:** в правой нижней части battle-2560 в песке видны два бледных
   круглых знака, похожих на водяной знак стоковой текстуры. Если рельеф где-то использует
   растровую заливку — это противоречит правилу «без растровых ассетов».

## 5. Момент попадания

**Диагноз.** На explosion-1280 взрыв — идеальный круг с мягким сглаженным градиентом, без
пиксельной решётки, без кратера, без частиц, без вспышки на рельефе; рядом в том же кадре
пиксельные облака и ступенчатые горы. «Так себе» — это не про палитру и не про радиус:
вспышка нарисована в другой технике, чем сцена. Пока это так, различия в цвете и скорости не
спасут — все четыре типа читаются как «мягкий кружок другого оттенка».

**Что важнее для различимости, по порядку:** 1) силуэт — опознаётся за кадр, не зависит от
фона; 2) след на рельефе — единственный различитель, который живёт после анимации (реплей,
скриншот, возврат взгляда); 3) ритм — сильно работает у кластера, слабо у остальных; 4) цвет — последний: палитра занята семантикой, а на закате оранжевый взрыв над оранжевым
песком не читается.

**Решение.**

- **Шаг 0 (80% эффекта, одна функция).** Рисовать взрыв во внеэкранный канвас размером `r/S`
  и масштабировать целым `S` = мировой масштаб (3–4 px) при `imageSmoothingEnabled = false`.
  Формула та же, но ступенчатая. Альфу квантовать до 4 уровней — мягкое затухание вторая
  причина «мыла».
- **Шаг 1. Силуэт как подпись типа** (маска поверх той же формулы):

    | Тип     | Силуэт                                                                        | След на рельефе                                   |
    | ------- | ----------------------------------------------------------------------------- | ------------------------------------------------- |
    | Фугас   | круг + 8 коротких лучей, одно кольцо                                          | воронка r, кайма 2 px темнее                      |
    | Мощный  | ромб, медленный рост, отдельное кольцо ударной волны 1 px за радиусом вспышки | воронка 1.6r, вдвое глубже, обугленная кайма 4 px |
    | Кластер | пять малых кругов по дуге, включаются с шагом ~60 мс                          | пять мелких лунок в ряд — самый узнаваемый след   |
    | Роющий  | вертикаль: узкий конус вниз + фонтан пикселей вверх столбом 4 px              | узкий колодец глубиной 2r, шириной 0.5r           |

- **Шаг 2. Ритм — три фазы целыми кадрами:** 1 кадр белой вспышки (`#e9f5e6`, силуэт залит),
  рост 6–10 кадров по типу, затухание не альфа-фейдом, а dissolve по детерминированной от
  сида маске. Плавный alpha-fade круга сильнее всего читается как дешёвый эффект.
- **Шаг 3. Цвет — два токена на тип:** фугас `#ffa900`/`#ff4242`, мощный `#ff4242`/`#c900ff`,
  кластер `#ffc21f`/`#ffa900`, роющий `#a2bb9d`/`#2c3f30` (земля, не огонь). Первый кадр у
  всех белый — различие начинается со второго.
- **`prefers-reduced-motion`:** роста нет, 2 кадра вспышки силуэтом и сразу конечный кратер.
  Тип остаётся читаемым, потому что несут его силуэт и след.

**Проверка.** Тест-плашка «стоп-кадр на 50%, четыре типа рядом, ч/б, 64×64» — различимы без
цвета и в мелком размере; по краю вспышки нет промежуточной альфы (≤ 4 значения), масштабы
целые; скриншот рельефа через 1 с — четыре разных профиля кратера; два прогона одного сида
дают побитово одинаковый PNG (dissolve-маска из сидового потока).

## 6. Небо и время суток

**Диагноз.** Сравнить battle-1280 (ночь) и explosion-1280 (день): небо и облака разные, а
песок, горы и танки — одного цвета. Ночью песок такой же насыщенно-оранжевый, как в полдень.
Освещение живёт только в верхней трети кадра и не доходит до земли. Светила нет — значит нет
источника света, направления, тени и повода для оранжевого заката.

**Решение по убыванию отдачи.**

1. **Тонировка земли от пресета** — плоский слой поверх рельефа и танков, до масштабирования:
   ночь `#101711` ~28%, закат `#ffa900` ~16% сверху + `#c900ff` ~8% в тенях, день 0%.
2. **Светило** — диск целых пиксельных размеров (диаметр кратен S), позиция от сида. Солнце:
   без нимба, 4 спицы по осям. Луна: 2–3 кратера в 1 px, трёхступенчатый нимб.
3. **Тень и подсветка кромок от светила** — тень танка эллипсом 2 px в противоположную
   сторону, у дальних гор контур 1 px по обращённому склону. Это и «включает» время суток:
   без светила сцена раскрашена, со светилом — освещена.
4. **Облака — три класса паралакса** (подтверждаю #515: сейчас размеры почти одинаковы и
   яркость одна): дальние (мелкие, 40% альфы, 0.3× ветра), средние (1×), ближние (крупные,
   уходят за край, 1.5×). Цвет смешивается с цветом светила: на закате подсвечено дно.
5. **Звёзды ночью** — точки 1 px от сида, две яркости, без мерцания (или 1 из 20 и off при
   `prefers-reduced-motion`).

**Проверка.** Вырезать 200×200 из песка на трёх сидах — средний цвет различается (ΔE > 15);
сейчас он практически одинаков, и это числовая формулировка «не читается как время суток».
Светило присутствует, его bbox одинаков при одном сиде и разный при разных. Глазами:
направление тени противоположно светилу; на ночном кадре есть звёзды, на дневном нет.

## Что упирается в ограничения

Ничего из §1–§4 не требует пересмотра бюджета высоты: мобилка 168 из 174, десктоп ровно 78,
планшет 124–136 (и впервые совпадает с объявленным инсетом зоны жеста).

Пересмотра требуют два места, оба не про высоту:

- **удаление ячейки «Снаряды» на десктопе** — если её наличие обязательно, правку надо
  отменять целиком: половинчатый вариант («оставить, но сжать») вернёт клип #489 при первом
  длинном нике;
- **тонировка рельефа** добавляет композитный проход по площади арены за кадр; при проблемах
  с FPS запекается один раз в генерацию рельефа.
