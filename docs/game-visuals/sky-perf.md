# Слоистое небо (#479): замер кадра до/после

Критерий готовности #479 — «кадр не проседает: замер до/после на мобильном профиле».
Ниже — методика и цифры, приложенные к PR фазы «Небо и параллакс».

## Методика

- **Профиль:** мобильный — вьюпорт `390×844`, CPU-throttling **6×** через CDP
  (`Emulation.setCPUThrottlingRate`), эмуляция слабого телефона (взят запас сверх
  4×, чтобы любая лишняя работа кадра вылезла просадкой).
- **Замер:** распределение времени кадра по `requestAnimationFrame` за окно 6 c
  (≈360 кадров) на боевой странице `/game`, по два прогона на состояние. Метрики —
  средний FPS, медиана/p95/худший кадр, число «янк»-кадров (> 20 мс).
- **До/после:** «после» — текущая ветка (`SkyBackground` под канвасом); «до» —
  та же ветка с временно снятым `<SkyBackground/>` (чёрный фон, как было).
  Обе сцены сняты скриншотом до замера (небо есть / фон чёрный) — чтобы замер
  точно относился к нужному состоянию, а не к недоприменённой правке. Оба замера —
  на прогретой dev-странице (fast-refresh применяет снятие неба), под одним троттлингом.

## Результат

| Состояние       | Средний FPS | Медиана | p95     | Худший кадр | Янк-кадры (>20 мс) |
| --------------- | ----------- | ------- | ------- | ----------- | ------------------ |
| До (чёрный фон) | 60.1 / 60.1 | 16.7 мс | 16.8 мс | 16.8 мс     | 0                  |
| После (с небом) | 60.2 / 60.3 | 16.7 мс | 16.8 мс | 16.8 мс     | 0                  |

Под 6× троттлингом бой держит залоченные 60 FPS **и с небом, и без** — ноль
пропущенных кадров в обоих случаях, распределение времени кадра совпадает.
Небо не вносит просадки.

### Почему замер тотального ScriptDuration не приводится

CDP `Performance.getMetrics` (ScriptDuration/TaskDuration) за окно в dev-режиме
доминируется **самим боем**, а он недетерминирован между навигациями: сид случайный
(`Date.now`), поэтому выстрелы бота, взрывы и тряска экрана каждый прогон дают разную
CPU-нагрузку, несопоставимую по величине. Стабильная сравнимая метрика — распределение
времени кадра, оно и приведено выше.

## Почему просадки нет по устройству кода

- **Статичный слой кешируется.** Градиент неба + силуэт гор рисуются в offscreen-канвас
  один раз и перестраиваются **только при ресайзе** (`SkyScene.ensureStatic`,
  `staticDirty`). Между кадрами фон не перерисовывается — идёт `drawImage` готового кеша.
- **Между кадрами двигаются лишь смещения.** `update(dt)` меняет два числовых `offset`
  облачных слоёв (по времени, не по кадрам), `draw` тайлит два спрайта. Аллокаций в кадре
  нет (`.claude/rules/canvas.md`).
- **`prefers-reduced-motion` глушит цикл.** Облака замирают, а rAF-петля неба после
  загрузки арта **останавливается совсем** (`SkyBackground.frame`: `reduced &&
allSkyImagesLoaded()` → `return`) — на устройствах с reduce-motion фон вообще не тратит
  кадры.
