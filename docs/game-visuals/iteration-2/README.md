# Итерация 2: по одному объекту за вызов

Уроки первой итерации применены: **один объект на вызов** (модель не держит количество),
**кадры взрыва по отдельности** с последующей сборкой листа, **автопроверки** вместо «на глаз».

| Файл                  | Что                       | Состояние                             |
| --------------------- | ------------------------- | ------------------------------------- |
| `clouds-near.png`     | ближний слой облаков      | в дело — редкие, отдельные, стык 0.0% |
| `hulls-sheet.png`     | лист из 5 корпусов        | в дело, заполнение в 24 px — 67–76%   |
| `hull-1…5.png`        | корпуса по отдельности    | в дело                                |
| `barrels.png`         | пять стволов              | проверить посадку к корпусам          |
| `explosion-sheet.png` | 4 кадра взрыва            | в дело, кадры не обрезаны             |
| `mockup-day.png`      | бой с новым небом         | —                                     |
| `mockup-presets.png`  | день / закат / ночь рядом | —                                     |

## Что поймали автопроверки

**Три корпуса из пяти пришли пустыми** — `gpt-image-1` с `background: transparent`
иногда возвращает полотно с нулевой альфой. Проверка «доля непрозрачных пикселей» это
показала (0%), лист собрался почти пустым, и пустышки не уехали в репозиторий.

Лечение: просить **сплошной пурпурный фон** (`#FF00FF`) и вырезать его самим —
после этого вырезается 76–84% кадра, силуэты плотные, заполнение в 24 px выросло
с 21% до 67–76%.

## Метрики

- **Бесшовность**: сравнение альфы левой и правой кромки — `clouds-near` и `barrels` дали 0.0%.
- **Читаемость**: доля непрозрачных пикселей после уменьшения до 24 px (целевой размер
  танка на мобиле). Ниже ~30% — силуэт в бою не читается.
