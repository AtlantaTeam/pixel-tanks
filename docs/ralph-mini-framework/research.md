# Research: маршрут подключения не-Claude моделей (Kimi / OpenAI)

**Трек:** «Фреймворк ralph», фаза 6 (агент-рантаймы + AGENTS.md).
**Issue:** #372. **PRD:** `docs/ralph-mini-framework/prd.md` (§«В скоупе» п.7),
**план:** `docs/ralph-mini-framework/plan.md` (фаза 6).
**Дата:** 2026-07-29
**Статус:** принято.

## Вопрос

Как подключить кодер-сессию на **Kimi** и **OpenAI**, не ломая Claude-путь. Три
кандидата из issue:

- **(а)** Anthropic-совместимый endpoint (Kimi K2) через env Claude CLI —
  один и тот же бинарь `claude`, другой `ANTHROPIC_BASE_URL`;
- **(б)** отдельный CLI под провайдера (OpenAI Codex CLI и др.) за интерфейсом
  рантайма;
- **(в)** комбинация: маршрут выбирается под провайдера.

Оценка по осям issue: формат стрима, permission-режимы, инструкции (AGENTS.md),
стоимость поддержки.

## Решение

**Комбинация (в): маршрут — под провайдера, оба за одним швом.**

| Провайдер  | Маршрут                                | Бинарь / вызов                | Файл инструкций |
| ---------- | -------------------------------------- | ----------------------------- | --------------- |
| **Claude** | эталон (без изменений)                 | `claude -p …` (`spawnClaude`) | `CLAUDE.md`     |
| **Kimi**   | **(а)** Anthropic-совместимый endpoint | `claude -p …` + env Moonshot  | `CLAUDE.md`     |
| **OpenAI** | **(б)** отдельный CLI                  | `codex exec …`                | `AGENTS.md`     |

Оба новых рантайма реализуют **уже существующий** контракт
`CoderRuntimeAdapter` (`.claude/ralph/adapters/adapters.ts`, §5) и подключаются через
`ralph.config.json` → `adapters.coderRuntime` (ключи `kimi` / `openai`
добавляются в реестр `coderRuntime` в composition root оркестратора — тем же
путём, что уже описан в докблоке `adapters-impl.ts`: «фаза 6 добавит ключи в
`coderRuntime`, Claude-путь не трогая»). Ядро зависит только от интерфейса
`RalphAdapters` — новый рантайм это правка **реестра**, не кода петли.

### Почему у Kimi — endpoint, а не свой CLI

Moonshot AI отдаёт **первосортный Anthropic-совместимый endpoint**
(`https://api.moonshot.ai/anthropic`, международный; `api.moonshot.cn` — для КНР).
Его потребляет **тот же** бинарь `claude`, которым ralph уже работает: достаточно
env `ANTHROPIC_BASE_URL` + `ANTHROPIC_AUTH_TOKEN` и `--model kimi-k2…`. Это значит:

- **spawn-путь не форкается** — Kimi-рантайм это `spawnClaude`/`buildClaudeArgs`,
  параметризованные окружением, а не второй канал исполнения;
- **бесплатно наследуются инварианты Claude-пути**: скан вывода на маркер
  API-лимита, `--permission-mode`, `--max-turns`, `--fallback-model`,
  таймаут, anti-RCE argv (`shell:false`);
- Kimi через `claude` читает **`CLAUDE.md`** (это тот же клиент) — AGENTS.md ему
  не нужен.

Ставить ради Kimi отдельный CLI не за что: env-своп покрывает всё, а новый бинарь
только добавил бы поверхность отказа.

### Почему у OpenAI — свой CLI, а не тот же endpoint

API OpenAI **не Anthropic-совместим нативно**. Прогнать GPT через `claude` можно
лишь **транслирующим прокси** (LiteLLM / claude-code-router) — это отдельный
stateful-процесс в петле, который может **молча исказить** трансляцию tool-call'ов
или стрима. Для fail-closed-петли (инвариант №1 в `.claude/ralph/CLAUDE.md`) лишний
безнадзорный переводчик между агентом и форжем — плохой размен: тихий сбой хуже
явного. Первопартийный путь OpenAI — **Codex CLI** (`codex exec`), его OpenAI и
сопровождает. Поэтому OpenAI = отдельная реализация `CoderRuntimeAdapter` над
`codex exec`, рядом с Claude, а не поверх него.

## Оценка по осям issue

### Формат стрима — контракт `{code, output}` уже абстрагирует его

Ключевая находка: **ralph НЕ парсит стрим агента.** `spawnClaude` берёт
`stdio: ['ignore','pipe','pipe']`, склеивает `stdout`+`stderr` в один `output` и
**сканирует его подстроками** (маркер API-лимита `API_LIMIT_RE`), а `code` берёт из
кода возврата. Контракт шва — ровно `RunResult = { code, output }` (`adapters.ts`
§5: «результат — код возврата + собранный stdout+stderr; сканируется на маркер
API-лимита, **НЕ парсится как JSON — сознательно**»). Следствие: **новый формат
стрима не требует нового кода-парсера ни у одного провайдера.**

- **Claude / Kimi:** текстовый вывод `claude -p`, склейка как сейчас.
- **OpenAI Codex:** `codex exec` по умолчанию пишет **прогресс в `stderr`, финальное
  сообщение в `stdout`** (текст). Ralph склеивает оба потока — этого достаточно;
  режим `--json` (JSONL-события `thread.started`/`item.*`/`turn.completed`)
  **не нужен** и не включается. Т.е. текстовый режим Codex ложится на тот же
  контракт, что и Claude.

### Permission-режимы

- **Claude / Kimi:** `--permission-mode bypassPermissions` (как сейчас в конфиге).
- **OpenAI Codex:** non-interactive `codex exec` при запросе аппрува **немедленно
  падает**, поэтому для AFK-петли нужен явный авто-режим: `-a never` (не спрашивать
  аппрув) + `-s danger-full-access` (или `workspace-write`) — рантайм крутится в
  **изолированном worktree раннера** (сосед репозитория, инвариант №3), где полный
  доступ к дереву и есть рабочая посадка. Устаревший `--full-auto` не использовать —
  задавать sandbox явным флагом.
- **Инъекции (C3) — слой не провайдерский.** Репо публичный + bypass = тело issue
  исполняется как инструкции. Защита (`authorAllowlist`, фильтр чужих авторов,
  делимитеры диффа в ревью) живёт в `taskSource`/ревью, **до** выбора рантайма, и
  на смену провайдера не завязана — новый рантайм её не ослабляет и не дублирует.

### Инструкции (AGENTS.md)

- **Claude / Kimi** читают `CLAUDE.md` (тот же клиент) — уже есть.
- **OpenAI Codex** читает **`AGENTS.md`**. Отсюда отдельная задача фазы **#375**
  (AGENTS.md-инфра): проектные инструкции для не-Claude агентов + **дрейф-проверка
  относительно `CLAUDE.md` в гейте** — чтобы два файла инструкций не разъезжались
  (детерминированный барьер, инвариант №5 «барьеры важнее промптов», а не «не забыть
  обновить руками»). Промпт-контракт петли (`ralph.md` + `ralph.project.md`) не
  дублируется в AGENTS.md: AGENTS.md несёт **проектные** конвенции (стек, темы,
  UI-контроль) для агента, у которого нет CLAUDE.md; общий контракт петли рантайм
  получает тем же способом, что и Claude (текст промпта сессии).

### Стоимость поддержки

- **Kimi ≈ тривиально:** env + имя модели, переиспользует весь Claude-путь. Риск
  минимален (нет нового бинаря, нет нового парсера, нет новой permission-модели).
- **OpenAI = один новый модуль-адаптер** (сборка argv `codex exec` + инъекция env
  ключа) за швом `CoderRuntimeAdapter`. Изолирован: Claude-путь байт-в-байт прежний,
  сценарные тесты Claude зелёные. Плюс AGENTS.md-инфра (#375).
- **Прокси-маршрут для OpenAI отвергнут:** лишний процесс, риск тихой мистрансляции,
  нарушение fail-closed — цена поддержки выше, чем свой adapter над первопартийным
  CLI.

## Секреты (инвариант №11 — только из env)

- **Kimi:** `ANTHROPIC_AUTH_TOKEN` (ключ Moonshot) + `ANTHROPIC_BASE_URL` — через
  окружение процесса `claude`, **не** в argv (не светятся в `/proc/*/cmdline`),
  редактируются в логах.
- **OpenAI:** `OPENAI_API_KEY` — Codex CLI берёт из env, не из argv. Хорошо ложится
  на текущее правило «секреты в env-файле раннера», без нового канала.

## Границы и известные риски (для #373/#374, смоук)

1. **Маркер API-лимита провайдер-специфичен.** `API_LIMIT_RE` матчит формулировку
   rate-limit именно Claude. Kimi/OpenAI при своём лимите дадут **другой** текст —
   цикл ожидания API-лимита оркестратора его не распознает и обойдётся с сессией как
   с обычным ненулевым завершением (ретрай/провал итерации). Для **смоука** (#373/#374)
   это приемлемо; провайдер-осведомлённый маркер — кандидат в отдельную задачу, **не
   в скоуп фазы** (не расширять карточки смоука).
2. **`modelRouting` становится провайдер-осведомлённым (#376):** label
   `complexity:*` → модель **любого** провайдера; выбор рантайма (`adapters.coderRuntime`)
   и выбор модели (`modelRouting`) — две ортогональные оси конфига, их стыковку
   делает #376.
3. **`--fallback-model` — только Claude-семантика.** У Kimi через `claude` работает
   как есть; у Codex понятия «fallback-model» в том же виде нет — для OpenAI-рантайма
   фолбэк-политика либо отсутствует (honest-стоп), либо решается на уровне
   `modelRouting`/повторной итерации, а не флагом сессии. Зафиксировать при
   реализации #374, не тащить Claude-флаг в чужой argv.

## Claude-путь НЕ меняется (критерий готовности #372)

Явно фиксируется: рантайм `claude` (`createClaudeRuntime`, `spawnClaude`,
`buildClaudeArgs`, `runClaudeOnce`), скан вывода на API-лимит, `--permission-mode`,
`--max-turns`, `--fallback-model`, таймаут и anti-RCE argv **остаются как есть**.
Kimi не форкает Claude-код — он его **параметризует окружением**. OpenAI —
**отдельный** адаптер, добавляемый **рядом**, а не поверх Claude. Дефолт
`adapters.coderRuntime` остаётся `claude` (`ADAPTER_DEFAULTS`), поведение петли на
текущем проекте не меняется; сценарные тесты Claude-пути должны остаться зелёными —
это критерий готовности фазы 6 в плане.

## Что из этого следует для остальных issue фазы 6

- **#373 (Kimi-рантайм):** ключ `kimi` в реестре `coderRuntime` = Claude-spawn с
  инъекцией env (`ANTHROPIC_BASE_URL`/`ANTHROPIC_AUTH_TOKEN`/`--model`); смоук —
  тестовая задача через `adapters.coderRuntime: 'kimi'`.
- **#374 (OpenAI-рантайм):** ключ `openai` = адаптер над `codex exec`
  (`-a never -s …`, текстовый вывод, env `OPENAI_API_KEY`); смоук — тестовая задача.
- **#375 (AGENTS.md-инфра):** `AGENTS.md` для не-Claude агентов + дрейф-проверка
  относительно `CLAUDE.md` в гейте.
- **#376 (provider-aware `modelRouting`):** label сложности → модель любого
  провайдера; ортогонально выбору рантайма.
