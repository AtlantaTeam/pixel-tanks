# Plan: ralph как мини-фреймворк

**PRD:** docs/ralph-mini-framework/prd.md
**Дата:** 2026-07-28

Трек milestone'ов: «Фреймворк ralph · Фаза N: …». Существующие бэклог-issues
(#232, #145, #252, #204, #262) привязываются к своим фазам, не дублируются.
Каждая фаза обязана оставлять раннер работоспособным: полный тестовый прогон +
`--dry-run` раннера — часть сдачи каждой фазы (входит в критерии готовности,
отдельными задачами не оформляется).

## Фазы реализации

### Фаза 1: TS-фундамент — util-модуль и side-effect-guard

**Цель:** Tracer bullet: первые TS-модули ядра, исполняемые Node 24 нативно (type
stripping, без билд-шага) и подключённые в живой раннер; снимает дубли утилит
(#232, #145).
**Затрагивает:** devops (`.claude/ralph/`, `scripts/`)
**Задачи:**

- [ ] Util-модуль на TS + tsconfig ядра (erasable-only) + typecheck ядра в гейте:
      **чистые** утилиты `shq` / `positiveIntOrDefault` / `sleep` — с тестами (#232)
- [ ] Side-effect-guard (`RALPH_NO_SIDE_EFFECTS`) как TS-модуль с тестами (#145)
- [ ] Подключить модули в `ralph.js` / `monitor.js` / `deadman.js` / гейт-скрипты, удалить дубли

`loadJson` (ralph.js) ≡ `readJSON` (monitor.js) читают диск (`readFileSync`), поэтому
в чистый без-побочек `ralph-util.ts` не попадают — их дом — модуль state/io **фазы 2**
(«Модуль state/lock», см. ниже), где живёт вся файловая обвязка. #358 в списке фазы 1
loadJson не называет; перенос зафиксирован здесь, чтобы дубль закрылся вместе со своим
слоем, а не размывал границу чистого util-модуля.

**Когда готова:** grep не находит копий **чистых** утилит (`shq`/`positiveIntOrDefault`/
`sleep`) вне модуля; `tsc --noEmit` по ядру зелёный; раннер стартует без билд-шага;
полный сьют + `--dry-run` зелёные.

### Фаза 2: argv-изоляция и инфраструктурные модули

**Цель:** В ядре не остаётся shell-интерполяции (#252); инфраструктурная обвязка
выделена в TS-модули с тестами.
**Затрагивает:** devops
**Задачи:**

- [ ] Остаток вызовов `sh(строка)` → `shArgv(file, args)`; grep-тест на отсутствие интерполяции (#252)
- [ ] Модуль state/lock (ralph.state.json, lock, deps-lock-маркер) — форматы файлов не меняются; сюда же общий `loadJson`/`readJSON` (файловое чтение JSON с фолбэком, дубль ralph.js↔monitor.js из фазы 1)
- [ ] Модуль worktree-менеджмента раннера
- [ ] Модули api-limit (парсинг/ожидание) и туннель-чека

**Когда готова:** grep-тест на `sh(` с интерполяцией зелёный; выделенные модули
покрыты перенесёнными тестами; сценарные тесты lock/deadman/hold зелёные;
`--dry-run` проходит.

### Фаза 3: процессные модули и entry на TypeScript

**Цель:** Монолит распилен до конца: гейт, ревью, деплой и оркестратор петли —
отдельные TS-модули, `ralph.js` заменён тонким entry.
**Затрагивает:** devops
**Задачи:**

- [x] Модуль гейта (исполнение шагов, heal-попытки, blocked-логика) + тесты
- [x] Модуль ревью (роутинг моделей, эскалация, журнал находок) + тесты
- [x] Модуль деплой-проверки (workflow-поллинг, health-чек) + тесты
- [x] Оркестратор петли + тонкий entry (`ralph.js` → модульное TS-ядро), флаги CLI без изменений
- [x] Разнести `ralph.test.js` (7079 строк) по модульным тест-файлам

**Когда готова:** монолитного `ralph.js` больше нет (entry — тонкая обёртка); все
сценарные тесты зелёные без изменения сути сценариев; живой `--dry-run` проходит.

### Фаза 4: конфиг-граница — проектная специфика из кода в конфиг

**Цель:** Ядро ничего не знает про pixel-tanks (#204): состав гейта, URL, пути —
только в `ralph.config.json`.
**Затрагивает:** devops
**Задачи:**

- [ ] Вынести проектную специфику в конфиг со схемой и валидацией: `GATE_STEPS` и опциональные шаги, health-URL, имя worktree, пути гейт-скриптов, пост-мердж команды; тест «шаг гейта меняется конфигом без правки кода» (#204)
- [ ] Grep-тест: `pixel-tanks|pixeltanks|AtlantaTeam` в ядре отсутствуют (включая дефолты-фолбэки)
- [ ] Актуализировать `ralph.config.json` текущего проекта под новую схему

**Когда готова:** grep-тест пуст; конфиг-тест зелёный; раннер на текущем проекте
работает без изменения поведения.

**Затрагивает:** devops
**Задачи:**

- [ ] TS-интерфейсы адаптеров: источник задач, гейт, нотификатор, деплой-проверка, рантайм кодер-сессии (#262)
- [ ] Оформить текущие реализации (GitHub issues/milestones, npm-гейт, Telegram, Actions+health, Claude CLI) как адаптеры, подключение через конфиг
- [ ] Контрактные тесты интерфейсов адаптеров
- [ ] Фикстурный мини-проект с чужим конфигом + тест: dry-run инициализации и плана фазы без ошибок
