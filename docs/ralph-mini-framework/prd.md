# PRD: ralph как мини-фреймворк

**Дата**: 2026-07-28
**Статус**: Draft

Закрывает бэклог-issues: #262 (адаптеры), #204 (конфиг-граница), #232 (util-модуль),
#145 (side-effect-guard), #252 (argv вместо sh()).

## Цель

Превратить раннер ralph из монолитного скрипта, прошитого спецификой pixel-tanks, в
переиспользуемый мини-фреймворк: ядро петли (issue → код → PR → ревью → гейт → мердж)
отделено от проектных деталей, подключение к другому проекту — конфиг + адаптеры, без
правки кода ядра. Это же снимает потолок роста: новые функции петли добавляются в
модульное ядро, а не в файл на 4352 строки.

## Пользовательские сценарии

- Мейнтейнер подключает ralph к новому репозиторию → копирует ядро, пишет свой
  `ralph.config.json` (гейт, деплой, промпт, роутинг моделей) — код ядра не правит.
- Разработчик меняет состав гейта (добавить/убрать шаг) → правит только конфиг,
  раннер подхватывает без изменений кода.
- Разработчик расширяет функционал (другой нотификатор вместо Telegram, другой
  источник задач) → пишет адаптер по описанному интерфейсу, ядро не трогает.
- Оператор запускает раннер по RUNBOOK (tmux, профили, `--once`/`--dry-run`) →
  поведение петли идентично текущему, процедуры запуска не меняются.
- Следующие улучшения петли (#215, #209, #253, #136) → реализуются как изменения
  одного модуля/адаптера, а не правка монолита.
- Оператор переключает кодер-сессию на альтернативный рантайм/модель (Kimi, OpenAI)
  через конфиг → петля работает, агент получает проектные инструкции (AGENTS.md).

## В скоупе

1. **Модуляризация ядра + TypeScript** (`.claude/ralph/`): распил `ralph.js` на
   модули с чёткими границами (петля, состояние/lock, worktree, гейт, ревью, деплой,
   API-лимиты, туннель). Модули ядра — на TypeScript, исполняются Node 24 нативно
   (type stripping), без билд-шага; typecheck ядра — часть гейта. Тесты переезжают
   за модулями (сейчас — один файл на 7079 строк).
2. **Общий util-модуль** (#232): `shq` / `positiveIntOrDefault` / `sleep` и прочие
   копии по файлам (`ralph.js`, `monitor.js`, `deadman.js`, скрипты) — один модуль.
3. **Side-effect-guard как модуль** (#145): единый механизм `RALPH_NO_SIDE_EFFECTS`
   для всех исполняемых частей.
4. **Довести argv-изоляцию** (#252): остаток вызовов `sh(строка)` переведён на
   `shArgv(file, args)`; строковая интерполяция команд в ядре отсутствует.
5. **Конфиг-граница** (#204): вся проектная специфика — в `ralph.config.json`:
   состав и порядок шагов гейта (сейчас `GATE_STEPS` зашит в код), health-URL,
   имя worktree, пути гейт-скриптов (`scripts/*.mjs`), команды пост-мердж хуков.
   В коде ядра не остаётся упоминаний pixel-tanks.
6. **Интерфейсы адаптеров** (#262): описанные контракты для точек расширения —
   источник задач (GitHub issues/milestones), гейт (композиция команд), нотификатор
   (Telegram), деплой-проверка (GitHub Actions + health). Текущие реализации
   становятся первыми адаптерами и подключаются через конфиг.
7. **Альтернативные агент-рантаймы**: интерфейс «рантайм кодер-сессии» как одна из
   точек расширения; поддержка моделей **Kimi** и **OpenAI** — выбор через конфиг
   (маршрут подключения — Anthropic-совместимый endpoint или отдельный CLI —
   выбирается research'ем в начале фазы); **AGENTS.md-инфра**: проектные инструкции
   для не-Claude агентов + контроль дрейфа относительно CLAUDE.md;
   provider-aware роутинг моделей по label'ам сложности.
8. **Проверка переносимости**: dry-run ядра на минимальном фикстурном проекте с
   другим конфигом (инициализация, план фазы — без реального Claude/GitHub).
9. **Документация**: README фреймворка — архитектура, интерфейсы адаптеров,
   пошаговое подключение к новому проекту; актуализация RUNBOOK и ссылок на пути
   (в т.ч. `escalateOnPaths` в конфиге ревью).

## Не в скоупе

- **Отдельный репозиторий / npm-пакет** — до появления второго реального
  проекта-потребителя ядро живёт в этом репо.
- **Изменение поведения петли**: функциональные улучшения #215 (снятие blocked),
  #209 (гейт из снапшота origin/main), #253 (фактическая модель в логе), #136
  (приоритизация диффа), #229 (храповик) — отдельные задачи после распила.
- **Новые адаптеры сверх перечисленного** (GitLab-источник задач, другие
  мессенджеры и т.п.) — только интерфейсы, текущие реализации и рантаймы
  Claude/Kimi/OpenAI.
- **Переписывание monitor/deadman/telegram-notifier** — они уже модульные; их
  касаемся только в части общего util-модуля и side-effect-guard.
- **Изменение формата состояния** (`ralph.state.json`, lock, журналы) без
  необходимости.

## Технические ограничения

- **Ралф — боевая машина.** Изменения едут мелкими PR с человеческим ревью
  (эскалация ревью на `.claude/ralph/**` уже включена); big-bang запрещён — каждая
  фаза оставляет раннер работоспособным (`--dry-run` + полный тестовый прогон).
- **Ядро — Node.js без внешних зависимостей** (только `node:*` и локальные модули);
  это свойство сохранить — раннер обязан работать до `npm ci`. TypeScript — только
  через нативный type stripping Node ≥24 (локально и VDS — Node 24): **erasable-only
  синтаксис** (без `enum`, namespace-рантайма, parameter properties), явные
  расширения в импортах, никакого билд-шага и рантайм-зависимости от `typescript`
  (пакет нужен только для `tsc --noEmit`, он уже в dev-зависимостях).
- **Раннер детачит дерево на `origin/main`** — конфиг и код фаз обязаны быть
  смерджены, локальные правки петля не видит. Рефакторинг едет поэтапно через main.
- **Тесты не трогают живой git** — существующая страховка (память: `GIT_DIR` из env
  под git-хуком портит настоящий репо) обязана сохраниться во всех новых модулях.
- **Обратная совместимость запуска**: флаги (`--once`, `--dry-run`, `--reset`,
  `--resubmit`, `--profile`), пути state/lock/log и процедуры RUNBOOK не меняются.
- **Не-Claude рантаймы не ломают Claude-путь**: парсинг stream-json, permission-mode
  и max-turns — специфика Claude CLI, уезжает за интерфейс адаптера рантайма;
  Claude-адаптер остаётся эталонным и покрыт текущими сценарными тестами.
- Во время активного прогона раннера рефакторинг не мерджим (правило из памяти:
  конфиг и фазы на ходу не трогать); окно — пустая очередь.

## Критерии готовности

- [ ] `grep -rE 'pixel-tanks|pixeltanks|AtlantaTeam' <ядро>` — пусто: проектная
      специфика только в `ralph.config.json`.
- [ ] Ядро — на TypeScript: `tsc --noEmit` покрывает модули ядра и зелёный; раннер
      стартует нодой без билд-шага (`node ralph.ts …` или entry-обёртка).
- [ ] Состав гейта задаётся в конфиге; изменение шага гейта не требует правки кода
      (подтверждено тестом).
- [ ] В ядре нет `sh(строка)` с интерполяцией — только argv-вызовы (подтверждено
      grep-тестом, #252).
- [ ] Дубли `shq`/`sleep`/`positiveIntOrDefault` по файлам удалены — один
      util-модуль, на него есть тесты (#232, #145).
- [ ] Все существующие тестовые сценарии зелёные; поведение петли не изменилось
      (сценарные тесты lock/blocked/deadman/hold проходят без переписывания сути).
- [ ] Dry-run на фикстурном проекте с чужим конфигом проходит без ошибок.
- [ ] Интерфейсы адаптеров описаны в README; текущие GitHub/Telegram/гейт/деплой
      реализации подключены как адаптеры через конфиг.
- [ ] Кодер-сессия запускается с Kimi и с OpenAI выбором в конфиге — смоук-прогон
      тестовой задачи проходит на обоих.
- [ ] AGENTS.md существует и не дрейфует от проектных инструкций (проверка дрейфа
      в гейте).
- [ ] RUNBOOK и `escalateOnPaths` актуализированы под новую структуру файлов.
- [ ] Реальный прогон петли (одна итерация `--once` на тестовой фазе) проходит
      issue → PR → ревью → гейт → мердж как до рефакторинга.
