# Plan: Верстка дизайн-системы (кодификация инвентаря)

**PRD:** [prd.md](./prd.md)
**Дата:** 2026-07-24

Источник дизайна — `docs/design-system-theming/design-inventory.dc.html` (DotGothic16), кодифицируем
1:1. Каждая фаза даёт рабочий результат; статус фаз — на доске, не в этом файле.

## Фазы реализации

### Фаза 1: Токены + DotGothic16 self-host (Tracer Bullet)

**Цель:** фундамент — дисплейный шрифт и все токены совпадают с инвентарём; гейт билдится офлайн.
**Затрагивает:** frontend
**Задачи:**

- [ ] Вендорить `dotgothic16-latin.woff2` + `dotgothic16-cyrillic.woff2` в `public/fonts`, `@font-face` (unicode-range как у прочих), НЕ `next/font/google`.
- [ ] `--font-display: 'DotGothic16'`; заголовки/лого/`text-display/h1/h2` — на нём; Pixelify Sans убрать из display.
- [ ] Сверить палитру/эффекты/радиусы/типо-шкалу в `globals.css` с инвентарём, добить недостающее (напр. именованный `--glow-danger`).
- [ ] Тест `globals.theme.test` обновить под DotGothic16 и синхронизацию токенов.

**Когда готова:** заголовки рендерятся DotGothic16 (кириллица ровная), `npm run build` офлайн зелёный, тесты токенов зелёные.

### Фаза 2: Иконки — `<Icon>` + замена всех эмодзи + линт

**Цель:** единый источник иконок, ноль эмодзи-иконок в коде.
**Затрагивает:** frontend
**Задачи:**

- [ ] Извлечь SVG icon-set (28 имён) из `design-inventory.dc.html` → `shared/ui/icon` (`<Icon name>`, `currentColor`, тема-aware) + public API.
- [ ] Заменить все эмодзи/глифы в существующих компонентах/витрине на `<Icon>`.
- [ ] ESLint-правило `no-emoji-as-icon` (ловит пиктограммы, не трогает типографику `× → · —`).
- [ ] Тесты: рендер `<Icon>`, тема-переключение цвета, линт-правило (позитив/негатив).

**Когда готова:** `<Icon>` покрывает набор, 0 эмодзи-иконок в `src/`, ESLint-правило зелёное, тесты зелёные.

### Фаза 3: Атомы форм и контролов

**Цель:** ввод и переключатели из инвентаря как компоненты со всеми состояниями.
**Затрагивает:** frontend
**Задачи:**

- [ ] `TextInput` (email/пароль с eye-toggle; состояния: обычное/фокус/ошибка/disabled/плейсхолдер) + label.
- [ ] `SegmentedControl` / `Tabs` (активный на `--accent`/glow).
- [ ] `Toggle` (`role="switch"`, вкл/выкл, на токенах).
- [ ] Тесты поведения и состояний каждого компонента.

**Когда готова:** три компонента в `shared/ui` с public API, все состояния покрыты тестами, гейт зелёный.

### Фаза 4: Атомы данных и HUD-элементы

**Цель:** отображение статы/боя из инвентаря как компоненты.
**Затрагивает:** frontend
**Задачи:**

- [ ] `Avatar` / `FactionBadge` (тема через `data-faction`).
- [ ] `HPBar` (пороги цвета success→warning→danger, подпись HP табличными).
- [ ] `PipRow` (снаряды/ходы, активный/погашенный).
- [ ] `WeaponSelector` (иконки `wpn-*`) и `ChatBubble` (enemy-тема).
- [ ] Тесты: пороги HP, счётчики pip, тема фракции.

**Когда готова:** пять компонентов в `shared/ui` с тестами, детерминированные пороги/счётчики покрыты, гейт зелёный.

### Фаза 5: Обратная связь и состояния данных

**Цель:** переиспользуемые состояния загрузки/пусто/ошибка/тост.
**Затрагивает:** frontend
**Задачи:**

- [ ] `Toast` (`aria-live`, success/нейтраль/ошибка) с иконками.
- [ ] `Skeleton` (загрузка), `EmptyState`, `ErrorBanner` (+ повтор), `Spinner`.
- [ ] Тесты: `aria-live`, варианты, повтор в ErrorBanner.

**Когда готова:** компоненты состояний в `shared/ui` с тестами, a11y-атрибуты проверены, гейт зелёный.

### Фаза 6: Попапы и оверлеи

**Цель:** модалки боя из инвентаря.
**Затрагивает:** frontend
**Задачи:**

- [ ] `Dialog` game-over с `data-outcome` (победа/поражение меняют акцент), a11y (focus-trap/Esc уже есть — сверить).
- [ ] Экран/оверлей **Пауза/Настройки**: звук (+музыка/эффекты), «спокойный HUD» (`data-intensity=calm`), язык (Select), сложность (Select), кнопки Продолжить/Заново/В меню — на существующих компонентах и `Toggle`.
- [ ] Тесты: смена `data-outcome`, тумблеры/селекты паузы, открытие/закрытие.

**Когда готова:** game-over и Пауза/Настройки работают из `shared/ui`/`widgets`, тесты зелёные, гейт зелёный.

### Фаза 7: Витрина `/design-system` 1:1 + статичные срезы

**Цель:** витрина = точная копия инвентаря; все элементы и состояния показаны статично (мишень визрегрессии).
**Затрагивает:** frontend
**Задачи:**

- [ ] Привести `views/design-system` к инвентарю 1:1: header-локап, роль-подписи цветов, секции 01–13.
- [ ] Показать **каждое состояние каждого компонента отдельным статичным срезом** — убрать interaction-gated демонстрации (клики «открыть», фокусы/раскрытия по взаимодействию).
- [ ] Каталожные секции экранов (логин/профиль/бой дня/реплей/онбординг/utility) — статичные, данные-заглушки.
- [ ] Playwright по 390/768/1280/1920: скриншоты в `screenshots/`, консоль чистая.

**Когда готова:** `/design-system` визуально совпадает с инвентарём по 4 вьюпортам, нет вида доступного только по клику/фокусу, консоль без ошибок, гейт зелёный.
