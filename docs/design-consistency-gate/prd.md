# PRD: Дизайн-барьер консистентности (design-consistency-gate)

**Дата**: 2026-07-24
**Статус**: Draft

## Цель

Дать pixel-tanks строгую, машинно-проверяемую консистентность визуальных интерфейсов, которую одинаково соблюдают и человек, и автономная ralph-петля — через два детерминированных гейта: **линт «только дизайн-токены»** и **визуальную регрессию**. Это устраняет корневую проблему («нет строгой дизайн-системы → неконсистентный UI») способом, соответствующим принципу проекта «барьеры важнее промптов»: не уговоры в промпте, а красный гейт. Основано на ресёрче — `docs/design-system-tooling-research/`.

## Пользовательские сценарии

- Разработчик/агент пишет UI с произвольным значением (`w-[137px]`, `bg-[#ff0]`) → **линт-гейт краснеет**, требует токен-утилиту (`w-…`, `bg-primary`) → консистентность держится автоматически, без ревьюера.
- Автономный кодер случайно меняет вид уже одобренного экрана → **визуальная регрессия краснеет** на пиксельном diff → регресс не мержится.
- Человек намеренно меняет вид экрана → осознанно **обновляет baseline** (одобряет новый эталон) в рамках обычного PR-ревью.

## В скоупе

- Подключение **`@poupe/eslint-plugin-tailwindcss`** (Tailwind 4 `@theme`) с правилами `prefer-theme-tokens` и `no-arbitrary-value-overuse`, включёнными как **error** в `npm run lint`.
- Приведение существующего UI-кода к токенам, чтобы гейт стартовал зелёным (0 нарушений на момент включения).
- **Визуальная регрессия** ключевых НЕ-canvas экранов (меню, HUD, лидерборд, game-over) через **Playwright `toHaveScreenshot`**; baseline-скриншоты в репо; npm-скрипт с детерминированным pass/fail (exit-code).
- Интеграция обоих гейтов в детерминированный набор проверок — локально и в составе гейта ralph (`BASE_GATE_CHECKS`/`PROD_GATE_CHECKS`).
- `@theme`-токены в `globals.css` остаются единственным источником правды.
- Документация: список экранов под визрегрессией и процедура обновления baseline.

## Не в скоупе

- Миграция токенов на DTCG / Style Dictionary v4 (пока `@theme` достаточно; отдельная итерация при росте).
- Генеративная сторона: скилл `ui-ux-pro-max`, дизайн-ревью субагент — отдельно.
- Оформление как переносимый «дизайн-адаптер» ralph — это **#262**, не здесь.
- **Claude Design** (`claude.ai/design` + `/design-sync`) — **выбран** как человеко-ориентированный дизайн-инструмент (генеративная/вкусовая сторона: человек генерит и судит вид). В этом PRD не автоматизируется — барьер ниже его **дополняет**, а не заменяет (машина энфорсит консистентность того, что человек создал). Интеграция `/design-sync` (синк дизайн-системы репо ↔ облако) — отдельная итерация.
- Прочие GUI-редакторы (Pencil.dev / OpenPencil) — отвергнуты ресёрчем для headless-петли.
- Внешние SaaS визрегрессии (Chromatic) и Storybook/Loki — берём Playwright, он уже в стеке.
- Отдельный инструмент «human approve-flow» для baseline — обновление эталона идёт обычным PR-ревью человеком.
- Визуальная регрессия самого игрового Canvas-поля в движении.

## Технические ограничения

- **Tailwind 4 `@theme`**: `@poupe` заявлен под v4, но ранние v4-плагины давали false positives — проверить на реальном коде до включения как error.
- **Детерминизм визрегрессии**: скриншоты стабильны только при фиксированном рендере — self-hosted шрифт Press Start 2P (уже офлайн, ок), отключение анимаций (`prefers-reduced-motion`), фиксированный viewport и DPR. **Canvas-поле в движении недетерминировано** (частицы/`Math.random` по кадрам) → под визрегрессию берём только UI-хром, не игровое поле.
- **Гейт-чеки не ходят в сеть** (инвариант проекта): Playwright-браузер ставится локально, baseline в репо, без SaaS. Совместимо с РФ (нет внешних блокируемых сервисов).
- **Headless**: оба гейта обязаны проходить неинтерактивно на detached-checkout PR-головы в ralph-раннере и в CI.
- Первое включение линта не должно завалить гейт задним числом — миграция к токенам входит в скоуп.

## Критерии готовности

- [ ] `@poupe/eslint-plugin-tailwindcss` подключён; `prefer-theme-tokens` и `no-arbitrary-value-overuse` включены как **error**; `npm run lint` краснеет на `bg-[#...]`/`w-[..px]` и зелёный на токен-утилитах.
- [ ] Существующий код приведён к токенам — на момент мерджа `npm run lint` зелёный (0 нарушений).
- [ ] ≥4 ключевых не-canvas экрана (меню, HUD, лидерборд, game-over) покрыты Playwright-скриншотами; baseline закоммичен в репо.
- [ ] Есть npm-скрипт визрегрессии с детерминированным pass/fail; намеренное изменение вида требует явного обновления baseline (иначе гейт красный).
- [ ] Оба гейта проходят headless и без сети; добавлены в состав чеков ralph-гейта.
- [ ] Игровое Canvas-поле в движении явно исключено из визрегрессии.
- [ ] Документировано: какие экраны под визрегрессией и как обновлять baseline.
