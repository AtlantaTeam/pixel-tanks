# Визуальная регрессия боевой сцены

Барьер из issue #585: эталонные кадры арены `/game` на трёх пресетах неба.
Дополняет визрегрессию витрины `/design-system` — той сторожится UI-хром, здесь
сторожится то, что рисует канвас.

## Что покрыто

| Пресет неба | Сид боя        | Кадры                                        |
| ----------- | -------------- | -------------------------------------------- |
| День        | `vrt-day-2`    | старт · полёт снаряда · взрыв · после взрыва |
| Закат       | `vrt-sunset-1` | старт · полёт снаряда · взрыв · после взрыва |
| Ночь        | `vrt-night-9`  | старт · полёт снаряда · взрыв · после взрыва |

Всего 12 эталонов, `e2e-visual/__screenshots__/`, вьюпорт 1280×800, DPR 1.

**Три пресета — обязательны, не «для полноты».** Регресс тени #571 (полоса
594×2 px, откат #581) виден ТОЛЬКО на закате: направление света там пологое.
Один дневной кадр его бы пропустил.

Сид — единственный вход пресета неба: `pickSkyPreset` (`sky-preset.ts`) выбирает
его хешем сида, отдельного URL-параметра нет. Сиды подобраны перебором так, чтобы
дать каждый из трёх пресетов.

## Как запускать

```bash
npm run test:visual                 # сверить кадры с эталонами
npm run test:visual -- --update     # пересъёмка эталонов
npm run test:visual -- --skip-build # без пересборки (только если .next свежий)
```

Первый запуск собирает образ `<имя из package.json>-visual:node24-pw<версия>`
(`e2e-visual/Dockerfile`) — это единственный шаг, которому нужна сеть. Дальше
прогон офлайн: браузер вшит в образ.

## Почему в контейнере, а не на хосте

Растеризация шрифтов и канваса зависит от версии Chromium, freetype и fontconfig,
то есть от машины. Эталон **без допуска в пикселях** (`maxDiffPixels: 0`,
`threshold: 0`) воспроизводим только в одной среде — поэтому кадры снимаются в
образе `node:24`, а не там, где случайно оказался разработчик. Допуск «пара
пикселей» тут бесполезен: ровно в такой зазор и проехал бы регресс #571.

Обычный e2e (`npm run test:e2e`) идёт на хосте и этих спек не видит: у визуальной
регрессии свой конфиг (`playwright.visual.config.ts`) и свой каталог
(`e2e-visual/`). Смешивать нельзя — иначе хостовый прогон краснел бы на чужой
растеризации, и барьер отключили бы первым же «почини гейт».

## Чем держится детерминизм кадра

1. **Сид боя** — рельеф, ветер, пресет неба, светило, облака, скины танков.
2. **Остановленные часы страницы** (`page.clock.pauseAt`): Playwright подменяет
   `Date`, `performance.now` и `requestAnimationFrame`, поэтому кадр движка —
   функция от суммы `runFor`, а не от загрузки машины.
3. **Якорь по состоянию движка, а не по миллисекундам**: спека шагает симуляцию
   по кадру и ждёт `bulletInFlight` / `particlesAlive` из read-only хука
   `window.__gameDebug` (`game-debug.ts`). При разных ветре и рельефе снаряд летит
   разное время — фиксированное «снять на 2000-й мс» дало бы в одном пресете взрыв,
   а в другом пустое небо (так и случилось на первой версии спеки).
4. **`prefers-reduced-motion: reduce`** — облака стоят, CSS-анимации HUD не
   попадают в кадр в случайной фазе.
5. **Арт публикуется потребителям только после `decode()`** (`whenDecoded`,
   `shared/lib/canvas`). Это не украшение: `drawImage` сразу по событию `load`
   может нарисовать пусто, а тон силуэта гор кешируется в offscreen — из-за чего
   горы пропадали примерно в трети загрузок и не возвращались до конца боя.

## Правило: правишь отрисовку — обновляешь эталоны тем же PR

- Любая правка того, как выглядит сцена (`features/game-engine/**`: небо, рельеф,
  танки, снаряд, взрывы, тени, свет; арт в `public/art`, `public/game`), обязана
  ехать **вместе с пересъёмкой эталонов в том же PR**. PR, где вид изменился, а
  кадры прежние, неполон — как компонент `shared/ui` без секции на витрине.
- **Обновлённые кадры смотрит человек.** Пересъёмка эталона — это не «починил
  тест», а «одобрил новый вид»: судить воспринимаемую красоту машина не умеет, она
  лишь вмораживает вердикт человека в baseline (CLAUDE.md, «Дизайн-процесс»).
  Поэтому в описании PR — что именно изменилось на кадрах и почему это правильно.
- Кадр изменился неожиданно — это находка, а не помеха: сначала объясни разницу,
  потом решай, обновлять ли эталон.

## Чего барьер не сторожит

- Другие вьюпорты: эталоны сняты на 1280×800. Мобильную раскладку сторожат
  замеры e2e (`e2e/*viewports*.spec.ts`), не пиксели.
- Погодные слои (дождь/снег/пыль) в движении и бой целиком: кадры сняты на
  четырёх состояниях одного хода.
- Гейт мерджа: прогон **пока не входит** в `gate.checks` раннера — ему нужен
  заранее собранный образ на прод-VDS, иначе первая же сборка образа в гейте
  пойдёт в сеть (и в РФ — через туннель). Интеграция — отдельной задачей, после
  провижна образа.
