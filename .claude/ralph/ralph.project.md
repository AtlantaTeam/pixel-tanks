# Ralph Loop — проектные правила (pixel-tanks)

Проектная половина промпт-контракта кодер-сессии. Общий, переносимый контракт петли
(как брать issue, ветки, TDD, circuit breaker, blocked/hold, завершение) — в `ralph.md`;
здесь — специфика **этого** репозитория: стек, тема, визуальный контроль. При переносе
раннера в другой проект (#204) `ralph.md` берётся как есть, а этот файл заменяется своим.

## Трекер: какие метки допустимы

Площадка — **GitHub**. Из этого важно ровно одно: **ты в неё не ходишь** — ни командой
`gh`, ни HTTP-запросом. Всё, что нужно ПРОЧИТАТЬ (тело задачи, комментарии ревью), раннер
прикладывает к промпту сам; всё, что нужно ИЗМЕНИТЬ, оформляется намерением по правилам
`ralph.md`, и применяет его тоже раннер.

Метки для намерения «заведи карточку» (ровно одна `complexity:*` и ровно одна `area:*`):

| Группа         | Значения                                                     |
| -------------- | ------------------------------------------------------------ |
| `complexity:*` | `low`, `medium`, `high`, `expert` — по ней выбирается модель |
| `area:*`       | `backend`, `core`, `frontend`, `devops`, `docs`              |
| `backlog`      | задача вне текущей фазы — ставится вместе с двумя верхними   |

Метки `blocked`, `hold` и `human` в намерении «заведи карточку» **не ставятся**: `blocked`
ставится отдельным намерением, `hold` и `human` — решения человека.

**Доску Projects намерение не трогает** — карточка заводится мимо неё, и раскладывает её
по доске человек. Это осознанная плата за то, что сессия не ходит в трекер: `gh project
item-add` — способ, а не намерение, и живёт он в адаптере, которому доска пока не нужна.

## Конвенции и правила проекта

- Используй существующие конвенции проекта: `CLAUDE.md` (корень) и `.claude/rules/`.
- Если для задачи есть research-документ (`docs/{feature}/research.md`) — следуй принятым
  там решениям, не выбирай библиотеки заново.

## Сборка как часть гейта

- Перед сдачей прогони `npm run build`: гейт мерджа проверяет и сборку, а `tsc`/тесты не
  ловят ошибки Turbopack/RSC (например, `'use server'`-модуль может экспортировать только
  async-функции). Полный состав чеков гейта — в `ralph.config.json` (`gate.checks`).

## UI-задачи: визуальный контроль (обязательно)

Если Issue затрагивает то, как игра выглядит или управляется (layout, HUD, тач, анимации,
страницы):

- ПЕРЕД вёрсткой запусти скилл `ui-ux-pro-max` (в репо, `.claude/skills/ui-ux-pro-max/`):
  `python .claude/skills/ui-ux-pro-max/scripts/search.py "<запрос>" --domain ux` (или
  `--design-system`) — возьми оттуда чек-лист под задачу. Путь проектно-относительный
  (cwd кодер-сессии = корень worktree), скилл закоммичен в репо — глобальный
  `~/.claude/skills/` не использовать: он не переживает restore VDS. Наша тема: retro
  pixel game (пиксель-арт, тёмный фон).
- ПОСЛЕ реализации проверь визуально через Playwright MCP: `npm run dev` (порт 3050) →
  навигация → скриншот в `screenshots/` → `browser_console_messages` (ошибок быть не
  должно). Вьюпорты — **все четыре канонных**: 390 (моб) / 768 (планшет) / 1280 (десктоп) /
  1920 (широкий). Планшет — целевое устройство, а не промежуточный размер: пропускать его
  нельзя (CLAUDE.md, «Адаптив»). Для экранов, играемых в landscape, добавь 667×375.
- Мало «не разваливается»: на каждом вьюпорте проверь, что **нет горизонтального
  переполнения** — `document.documentElement.scrollWidth` равен ширине вьюпорта, и ни один
  элемент не уходит за правый край. Замер ловит то, чего не видно на скриншоте: в макете
  игрового экрана телеметрия уезжала на 158px за край 768 при `scrollWidth: 768`, то есть
  контент был недоступен и не скроллился.
- Не закрывай Issue без визуальной проверки — «код написан» ≠ «выглядит правильно».

## Экран боя: спека дизайна — источник правды

Issue про боевой экран `/game` (HUD, тач-рогатка, состояния хода) сверяй с
`docs/design-system-theming/game-screen/handoff.md` — финальный хендофф Claude Design
(issue #280, ревизия 3): layout по слоям, точные значения, все состояния, модель состояния
стора. Разошлось с кодом — прав `handoff.md`, кроме пунктов, где он сам ссылается на «канон
кода» (пипы 14×14, HP-трек 12px, значения токенов). Рядом `pt-game.dc.html` —
параметризованный макет всех состояний.
