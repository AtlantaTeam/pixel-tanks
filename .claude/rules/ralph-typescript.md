# Раннер ralph: TypeScript по умолчанию

**Новый и правленый код раннера пишется на TypeScript.** JavaScript в `.claude/ralph/` —
не «как исторически сложилось», а исключение, которое обязано себя обосновать в докблоке
файла. Не уверен — бери `.ts`.

## Когда `.js` всё-таки допустим

Ровно один класс: **entry-точка, запускаемая напрямую** (`node .claude/ralph/<файл>.js`
человеком из tmux или спавном). Такой файл исполняется до того, как проверена версия Node,
поэтому сам обязан быть исполним на любой: на Node <24 первый же `require('*.ts')` падает
криптичным `ERR_UNKNOWN_FILE_EXTENSION` в глубине зависимостей вместо внятного отказа
(инвариант №1 — fail-closed). Образец — `ralph.js`.

Требования к такому entry:

- **тонкий**: проверка версии Node, разбор argv, вызов TS-ядра, ре-экспорт API — и всё.
  Логика живёт в `.ts`-модуле рядом;
- в шапке — докблок, объясняющий, **почему** файл не может быть `.ts`.

Модуль, который только `require`-ится (не запускается как процесс), под исключение
не подпадает — он `.ts` независимо от размера.

## Ограничения, из которых это следует

- **Ядро — Node без внешних зависимостей** (`node:*` + локальные модули): раннер обязан
  работать до `npm ci`. TS исполняется нативным type stripping Node 24, **без билд-шага**.
- Отсюда — **erasable-only синтаксис**: никаких `enum`, namespace-рантайма, parameter
  properties, декораторов. Пакет `typescript` нужен только для `tsc --noEmit`
  (`npm run typecheck:ralph` в гейте), в рантайме его нет.
- Импорты — **с явными расширениями** (`./ralph-util.ts`).
- Тест следует за своим модулем: `gate.ts` → `gate.test.ts`. Переводишь модуль в TS —
  его тест едет следом тем же PR.
- Перевод существующего `.js` в `.ts` — **отдельный PR, не попутно с фичей**: раннер
  боевой, дифф должен читаться как чистый перенос.

Причина строгости приземлённая: оболочка раннера разбирает форматы строк лога
(`deadman.ts` ↔ `apiLimitMessage`), и синхронность этого контракта сейчас держится
только тестом. Типы дешевле теста.
