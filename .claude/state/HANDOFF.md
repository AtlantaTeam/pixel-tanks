## Последние принятые решения

- **`common.phases` — очередь, а не история.** После каждой фазы: заменить `phases`
  отдельной веткой → PR → main → `--reset` → запуск. Конфиг читается ОДИН раз при старте,
  дозаказать фазу на ходу нельзя.
- **Порядок «код → доки» железный**: доки всегда последней фазой. Дважды за сессию
  приходилось разводить фазы именно из-за этого.
- **`.mts` vs `.ts`**: #403 выбрал `.mts` там, где нужен `import.meta.dirname` (в ESM нет
  `__dirname`) — явный ESM вместо «Node догадается». Побочный эффект: `.mts` не
  переразбирается, то есть #408 подешевел до механической раскатки на остальные 41 файл.
- **Правило TS-приоритета в main** (`.claude/rules/ralph-typescript.md`, PR #399): `.js`
  только для entry, запускаемой напрямую, тонкой и с обоснованием в докблоке.
- **#379 вынесен из milestone**: очередь фильтрует только `blocked` и чужих авторов,
  признака «делает человек» нет — раннер взял бы человеческую задачу. Барьер — **#410**, где
  отдельно оговорено, что такие карточки надо исключить И из проверки сдачи C2 (иначе фаза
  с человеческим хвостом не смерджится никогда).

## Что всплыло за сессию

- **Падение шага правок на 529 Overloaded** (фаза 8): сессия упала с exit 1, оставив 35
  файлов незакоммиченными, раннер встал fail-closed. Лечение (как 28.07): проверить
  осмысленность правок → прогнать чеки руками → закоммитить `--no-verify` → перезапустить.
  Хуки пропускать намеренно — тесты ралфа под git-хуком получают `GIT_DIR` из env и бьют по
  настоящему репо. Ревью раннер повторяет с нуля, и это правильно: неизвестно, всё ли
  успела применить упавшая сессия.
- **API-лимит дважды по ~100 мин** (opus на #405, fable на ревью). Ревью эскалируется на
  fable по `escalateOnPaths`, где `.claude/ralph/**` — вся папка, включая доки: правка
  докблока тянет самую дорогую модель.
- **`complexity` ≠ объём**: #405 (механический перенос 6195 строк) получил `high` за размер
  и ушёл на opus, где хватило бы sonnet. Ставить `high` за риск ошибки, а не за строки.
- Операционные грабли (push без прокси, `tmux send-keys` в занятое окно) — в памяти сессии.
