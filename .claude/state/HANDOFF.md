# Session Handoff

**Дата**: 2026-08-12

## Где остановились

Заведён трек **«Мобильная эргономика боя»** — три фазы, 12 карточек (#447–#458).
Петля запущена в профиле `prod` и **работает прямо сейчас**: фаза 1 сдана целиком,
PR #460 в ревью.

Поводом стали жалобы владельца на боевой экран: панель скачет, тост «летает»,
на мобилке не видно низ поля, танки огромные. Всё подтверждено замером, цифры — в
`docs/game-mobile-ergonomics/prd.md` (390×844, прод-сборка).

## Что нашли замером

| Что                                     | Было                            |
| --------------------------------------- | ------------------------------- |
| HUD, свой ход → ход соперника           | 280 → 332 px (33% → 39% экрана) |
| Палуба                                  | 202 px (24%)                    |
| Свободная арена                         | 310 px (37%)                    |
| Ячейка «Угол» при `1°` / `41°` / `360°` | 162 / 173 / 184 px              |
| Пилюля хода «ТВОЙ ХОД» / «ВЫСТРЕЛ»      | 152 / 142 px                    |

Танк — константы `60×30` px в `lib/tank.ts`, без привязки к арене. Низ ландшафта
физически под палубой. Побочно: `formatAngle(0) === 360` → HUD стартует с «УГОЛ 360°» (#457).

## Фазы и статус

1. **HUD не скачет** (#447 ✅, #448 ✅, #449 ✅) → PR #460, ревью opus.
2. **Компактные оверлеи** (#450–#452): HUD ≤ 180 px, палуба ≤ 150 px, арена ≥ 55%.
3. **Safe-зона арены и масштаб мира** (#453–#456): инсеты движку, танки внутри зоны,
   масштаб от ширины арены.

Вне фаз, бэклог: #457 (угол 360°), #458 (Playwright MCP ищет несуществующий
`/opt/google/chrome/chrome`, скриншоты приходится снимать скриптом).

## Решения

- **Тряска камеры и juice — не трогать.** Владелец их принял; в фазе 3 при масштабировании
  объектов соблазн поправить дрожание есть, и это прямо запрещено в PRD.
- Кнопки уменьшаем **визуально**: hit-area остаётся ≥ 44×44, зазор ≥ 8 px.
- Канвас остаётся полноэкранным; движок получает инсеты, а не ужимается в flex-колонку.

## ⛔ Первым делом утром: петля стоит на security

**PR #460 (фаза 1) помечен `blocked` — гейт красный на чеке `security`, и это не регресс
кода.** В ночь на 12.08 вышли шесть новых advisory в транзитивных зависимостях; чини-сессия
раннера правильно отказалась заметать их в baseline и упёрлась.

Разобрано в **#462**, готовый кусок — в **PR #463** (`npm audit fix`: закрыты `fast-uri`,
`js-yaml`, `nanoid`; билд и 2498 тестов зелёные). Оставшиеся два случая требуют **решения
человека**, поэтому и оставлены:

- `undici@7.24.4` запиннен `payload@3.84.1`. Фикс в `undici@7.29.0` — доехать можно только
  подъёмом payload до 3.88.0: мажорный шаг в CMS, нужна проверка админки, схемы БД и e2e.
- `image-size@2.0.2` — **патча не существует**, 2.0.2 последняя. Закрывается только записью
  в baseline с разбором достижимости (парсеры ICNS/JXL/HEIF у нас не вызываются).

Плюс `security-audit` сообщает, что baseline протух: записи 1124008 и 1124018 (`immutable`)
больше не находятся и подлежат удалению — это правка барьера, отдельным PR.

Порядок: смержить #463 → решить по payload и baseline → влить main в ветку фазы →
снять `blocked` с #460 → перезапустить петлю.

## Грабли запуска петли

- Env полигона — **`/root/pixel-tanks.env`**, не `/root/ralph.env` (там ключи medods-bridge).
- После «все фазы завершены» state пустой: добавив новые фазы, стартовать через
  `--reset` (иначе fail-closed «предыдущая фаза не смерджена»).
- Перед стартом снять мониторы-сироты: `pkill -f "\.claude/ralph/runtime/monitor\.js"`.
- Окна tmux: `1:ralph` — цикл, `2:monitor` — дашборд (монитору тоже нужен env, иначе
  «нет данных gh»).
